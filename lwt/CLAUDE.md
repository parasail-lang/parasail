## Overview

LWT is a Light-Weight Threading library for Ada 2022 that implements parallel features (`parallel for` loops and `parallel do` blocks) without requiring compiler support for the new syntax. It provides a plug-in-based scheduler architecture with two schedulers — OpenMP and Work-Stealing — plus a sequential fallback. Published as an [Alire](https://alire.ada.dev/) crate named `lwt`.

## Build Commands

**Prerequisites**: `gnat`, `gprbuild`, and optionally `alr` (Alire)

```bash
# Build the library via Alire
alr build

# Build the library directly
gprbuild -P lwt.gpr

# Build all examples
cd examples && gprbuild -P prj.gpr

# Build Ada 2022 examples
cd a22_examples && gprbuild -P prj.gpr

# Run a specific example (after building)
examples/obj/<example_name>
```

`common.gpr` is an abstract project with shared compiler/linker switches used by the examples. `lwt.gpr` uses `config/lwt_config.gpr` (generated by Alire) for switches and version info.

## Architecture

### Plug-in Scheduler Design

The library is structured around a pluggable scheduler interface. Users select a scheduler by:
1. `with`-ing `LWT.OpenMP` or `LWT.Work_Stealing` in their code
2. Declaring a control object (`OMP_Parallel` or `WS_Parallel`) in their main subprogram or task body — this activates the scheduler for the lifetime of that scope

If no scheduler is activated, all parallel constructs run sequentially.

### Key Packages

| Package | File(s) | Role |
|---|---|---|
| `LWT.Scheduler` | `lwt-scheduler.ad{s,b}` | Core API: `LWT_Group`, `Spawn_LWT`, `LWT_Range_Loop`, server index queries |
| `LWT.Parallelism` | `lwt-parallelism.ad{s,b}` | Higher-level API: `Par_Range_Loop`, parallel iterator interfaces (what the compiler calls) |
| `LWT.OpenMP` | `lwt-openmp.ad{s,b}`, `lwt-scheduler-openmp.ad{s,b}` | OpenMP scheduler plug-in; wraps `GOMP_task*` and `GOMP_parallel*` C interfaces |
| `LWT.Work_Stealing` | `lwt-work_stealing.ad{s,b}`, `lwt-scheduler-work_stealing.ad{s,b}` | Pure-Ada work-stealing scheduler plug-in |
| `LWT.Aspects` | `lwt-aspects.ads` | Root aspect type for passing hints to schedulers (e.g. `OMP_Taskloop`, `WS_Options`) |
| `LWT.Storage` | `lwt-storage.ad{s,b}` | Storage management for LWT data |
| `LWT.Statistics` | `lwt-statistics.ads` | Optional statistics collection |

### Parallel Iteration

- `lwt-generic_par_iterators.ad{s,b}` — generic parallel iterator
- `lwt-vector_par_iterators.ads` — parallel iterator for `Ada.Containers.Vectors`
- `lwt-hashed_map_par_iterators.ads` — parallel iterator for `Ada.Containers.Hashed_Maps`
- `lwt-generic_parallel_work_lists.ad{s,b}` — parallel work lists
- `lwt-generic_synchronized_deques.ad{s,b}` — synchronized deques used internally
- `lwt-generic_atomic_max_min.ad{s,b}` — atomic max/min for reductions

### Sorting

- `lwt-par_constrained_sort.ad{s,b}` — parallel constrained sort
- `lwt-par_constrained_bitonic_sort.ad{s,b}` — parallel bitonic sort

### Typical Usage Pattern

```ada
with LWT.Work_Stealing;  --  or LWT.OpenMP
with LWT.Parallelism;

procedure My_Main is
   Control : LWT.Work_Stealing.WS_Parallel (Num_Servers => 0);
   --  0 = use number of physical cores; activates scheduler for this scope
begin
   LWT.Parallelism.Par_Range_Loop
     (Low => 1, High => 1000,
      Loop_Body => (access procedure (Low, High : Longest_Integer; ...) is ...));
end My_Main;
```

See `examples/` for complete working programs covering parallel loops, N-queens, exception handling in parallel loops, sorting, and container iteration.
